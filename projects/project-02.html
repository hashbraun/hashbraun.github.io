PROJECT 02

Semi-Auto Labeling Tool with Construction-Safety Detector

with HDC LABS · Construction-site CCTV · 10-class · v1 deployed → v2 WBF mAP@0.5 0.670 (진행형)
YOLO26x / YOLOv11x / RT-DETR SAM2 WBF Ensemble BOTSORT + ReID FastAPI · Docker · SLURM Codex LLM-in-the-loop
Role AI Researcher
Period Jun. 2026 – Aug. 2026
Domain CV · Long-tail Detection · Labeling Ops
System overview · iterative label-pool 확장 루프. 결과: v1 attempt 2 배포 · v2 WBF ensemble mAP@0.5 = 0.670.

S · Situation

건설현장 CCTV용 12-클래스 중장비·작업자 검출기가 있었지만, 소수 클래스(펌프카·RMC 등)에 대한 성능이 사실상 무의미한 수준이었고, 대규모 라벨을 소량 시드로부터 부트스트랩하는 사내 세미오토 라벨링 툴(FastAPI + Docker + SLURM)에 그대로 얹기 어려웠다.

또한 학습 val-mAP가 실측 성능과 어긋나는, metric과 실측 사이의 괴리가 있었다.

T · Task

  • 소수 클래스를 살리는 방향으로 학습 데이터 분할과 클래스 스킴을 재설계한다.
  • 롱테일에 맞는 백본·해상도·증강 레시피를 결정한다.
  • 배포 판정 지표를 재정의하여, 사내 배포 결정을 리더보드 편향 없이 내릴 수 있게 한다.

A · Action

  • 데이터 스플릿 재구성 — scene-level 3-way split을 만들고, 소수 클래스는 val/test에 강제 할당해 저평가되지 않도록 함.
  • 클래스 스킴 12→10 — signalman은 person으로 병합, check는 신뢰도 기반 후처리 룰로 오프로딩.
  • YOLO26x · imgsz 1280 백본 채택 + 롱테일 구제용 증강 레시피 (cls=1.5, copy_paste=0.5, mixup=0.15, close_mosaic=30).
  • 배포 판정을 poc_eval per-class F1로 이동 — scene-held-out val은 본질적으로 어렵기 때문에, 별도의 holdout poc_eval 세트를 acceptance gate로 사용.
v2 detection pipeline · scene-level held-out → 9 attempts → 7-model WBF (+3.8pp) → deploy candidate + BOTSORT+ReID tracking.
Pump-car confusion fix · v1 (좌) 은 창문을 pump car로 대량 오검(long-tail bleed), v2 antiof1 (우) 은 window 로 정확히 회복 · conf ≥ 0.5.
Semi-Auto Labeling Tool UX · ① Pre-annotate → ② Human Review & Fix → ③ Apply & Retrain (SLURM + Codex).

v2 · Progression (Aug 2026)

v1 배포 직후 방법론과 데이터셋 규모를 근본적으로 재정비. 씬 단위 held-out 원칙을 세우고, 7개 attempt를 통제 실험으로 비교한 뒤 앙상블·트래킹까지 end-to-end로 확장.

1. 정직한 평가 확립

  • 기존 mixed test (5,916)를 test_poc (5,766 · 35 씬) / test_aihub (110) / test_wd (40) 로 소스별 분리 → pure CCTV 지표 확립.
  • 이전 mAP 95%는 프레임 단위 split의 leakage 부산물이었음을 확인. 씬 단위 held-out에선 실질 0.4~0.6 수준이 정직한 성능.

2. AIHub partial-label 회귀 진단

  • v2 att1 (mixed 학습)에서 person -3% · fork lift -7% 회귀 관측.
  • 원인: AIHub 237 라벨은 excavator만 존재 · 프레임 속 unlabeled person이 background로 학습되어 검출 억제.
  • 대응: SAM2 마스크 기반 crop 합성 파이프라인 (외형만 흡수, 환경은 PoC) — pre_extracted_bg 오염 77장 중 53장 발견 → 제외.

* v2 att1 confusion matrix (poc_eval, row-normalized %) — person 회귀는 실제로 대각선 63.6% + background 36.4% FN, dump truck은 86.8% background 오분류로 여전히 실패. 이 진단이 SAM2 crop 합성 대응의 근거가 됐다.

3. 9 attempt 통제 실험 + LLM-in-the-loop

* v2 9 attempt progression — att2 baseline 0.421 → antiof1 0.632. WBF 7-model ensemble이 최고 single (antiof1) 대비 +3.8pp 추가 (0.670).

test_poc: 학습에 쓰지 않은 35개 CCTV 비디오 · 5,766 프레임. 씬 단위 held-out = 같은 비디오 프레임이 train과 test에 절대 섞이지 않음 (프레임 단위 split의 부풀림 방지). mAP@0.5 = IoU 0.5 기준 클래스별 Average Precision 평균.

att2 (D=baseline poc-only) 0.421 att3 (C=poc+synth 5K) 0.455 (+3.4pp) ext1 (데이터 확장 37K, 155 씬) 0.589 (+13.4pp) tune1 (patience 0, aug 최소) 0.524 tune3 (cls=2.5, minority 강화) 0.592 hires1 (imgsz 1536) 0.554 rtdetr-x-v1 (Transformer) 0.498 yolo11x-v1 (신 YOLO) 0.615 antiof1 (AdamW + lr↓ + cls 0.8) ★ 0.632
  • codex JSON 검토 기반 auto-loop — 학습 완료 → 3-슬라이스 평가 → codex가 args.yaml 파라미터 제안 → 자동 재학습 → 반복 (regression alarm 자동 중단).
  • overfitting 원인 규명: val_cls_loss 폭증 (3~4×) = classification overconfidence 과적합. AdamW + lr 0.0005 + cls 가중치 0.8로 val_cls 6~12 → 0.31로 감쇠 확인 (antiof1).

5. Test-inclusion 재학습 (배포 최종)

  • 배포 카메라 = 학습 도메인이므로 held-out 검증 후 train + val + test_poc 모두 편입 재학습 (all-data 51K frames).
  • 산업 표준 pipeline (Kaggle 우승 · Waymo · Amazon SageMaker AutoML): 개발 시 held-out으로 방법 검증 → 배포용은 all data 재학습.
  • deploy-v1 후보 · antiof1 승자 설정 (AdamW + lr↓ + aug↓) 유지 · 예상 실배포 성능 0.85+.

6. End-to-end Tracking (BOTSORT + ReID)

  • JDE (Joint Detection & Embedding) 실무 등가로 Ultralytics BOTSORT + ReID (with_reid: True) 채택.
  • appearance-based re-identification으로 occlusion 복구 (사람이 트럭 뒤로 사라졌다 재등장해도 같은 ID 유지).
  • 실측 데모 (manual_css411202z045, 451 frames): dump truck·fork lift 2개 유효 ID 전 구간 안정 유지, max_conf 0.97~0.98.

* BOTSORT + ReID 실측 데모 — antiof1 detection + tracker on manual_css411202z045 (15 s · 451 frames). ID 1 fork lift (max_conf 0.98)와 ID 2 dump truck (max_conf 0.97)가 전 구간 안정 유지 (3rd ID는 1 frame 단발 FP). 재렌더 파이프라인: v4_tracking_demo.py + botsort_reid.yaml.

Δ · Lessons

  • 정직한 평가 > 화려한 지표. 이전 mAP 95%는 프레임 leakage로 부풀린 수치. 씬 단위 held-out으로 재정립한 0.6대가 실질.
  • Partial-label의 함정. 외부 데이터 편입 시 라벨 온톨로지 mismatch가 negative supervision을 유도해 오히려 회귀 유발. 합성으로 회피.
  • 데이터 다양성 > 하이퍼파라미터. 씬 다양성 5× (32→155)이 hyperparameter 튜닝 총합보다 큰 편익 (+14pp).
  • LLM-in-the-loop MLOps. codex의 파라미터 제안 + regression alarm이 4h 학습 낭비를 방지.
  • Held-out은 배포용 모델이 아님. 검증 후 all-data 재학습이 산업 표준. Test-inclusion 재학습은 leakage가 아니라 산업 관행.
