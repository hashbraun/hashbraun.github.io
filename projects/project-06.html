PROJECT 06

Dynamic Obstacle-Aware Path Replanning for a 6-DOF Robot Arm

인공지능종합설계 팀프로젝트 · UR5e (Gazebo Sim) · Reactive Recovery FSM

Period Aug. 2025 – Dec. 2025
Domain Robotics · Motion Planning (Sim)

깊이 카메라 관측을 점유 지도로 변환해 경로 계획에 반영하고, 지도 변화 이벤트에 따라 정지·후퇴·재계획·재개를 수행하는 흐름입니다.

프로젝트 개요. UR5e 시뮬레이션에서 깊이 카메라와 OctoMap으로 작업 공간을 갱신하고, MoveIt 2 경로 계획 중 동적 장애물 진입이 감지되면 Recovery FSM으로 정지·후퇴·재계획·재개를 수행하는 반응형 모션 플래닝 파이프라인을 구현했습니다.

01 · Problem Definition

정적 플래너만으로는 실행 중인 궤적에 갑자기 진입하는 동적 장애물에 대응하기 어렵습니다. 실제 UR5e 하드웨어에 적용하기 전에 Gazebo 시뮬레이션에서 장애물 감지부터 재계획까지 이어지는 반응형 파이프라인을 먼저 검증할 필요가 있었습니다.

팀 프로젝트의 개발 범위를 고려해 별도의 장애물 인식 모델을 학습하기보다, 지도 갱신 정보를 이용해 장애물 감지 → 정지 → 후퇴 → 재계획 → 재개가 연결되도록 시스템을 단순화했습니다.

02 · Scope & Design Goals

  • Gazebo 깊이 카메라 관측을 PointCloud와 OctoMap으로 변환하고 MoveIt Planning Scene에 반영함.
  • MoveIt 2·OMPL RRT-Connect 기반 관절 공간 경로 생성과 Continuous Collision Check 연결함.
  • 지도 변화 이벤트를 감지해 Stop → Back-off → Replan → Resume으로 이어지는 Recovery FSM 구현함.
  • UR5e 실물 적용 전 Gazebo에서 Perception–Planning–Control–Recovery 전체 흐름을 검증함.

03 · System Design & Implementation

깊이 영상에서 3차원 점유 지도 생성

Gazebo의 깊이 카메라에서 생성한 점군을 MoveIt의 OccupancyMapUpdater로 전달해 OctoMap을 갱신했습니다. 관측된 공간은 free·occupied·unknown 상태로 누적되며, 갱신된 점유 지도는 MoveIt Planning Scene에 반영되도록 연결했습니다.

경로 생성과 연속 충돌 검사

MoveIt 2와 OMPL의 RRT-Connect로 시작 상태에서 목표 상태까지 관절 공간 경로를 생성했습니다. 생성된 경로에는 Continuous Collision Check를 적용해 waypoint 사이 구간을 포함한 궤적의 충돌 여부를 확인하도록 구성했습니다.

지도 변화량 기반 복구 상태 머신

Planning Scene의 지도 데이터량(voxel bytes)을 주기적으로 비교하고, 변화량이 약 160 bytes 임계값을 넘으면 재계획 이벤트를 발생시켰습니다. Recovery FSM은 Monitor → Detect → Stop → Back-off → Replan → Resume 순서로 동작하며, UR5e의 이동·정지·재개는 JointTrajectory Controller를 통해 제어했습니다.

Perception, Planning, Control과 Recovery FSM의 연결 구조입니다. 센서 정보가 Planning Scene에 반영되고, 지도 변화 이벤트가 로봇 정지와 재계획을 트리거합니다.

OctoMap의 점유 지도 갱신 원리입니다. 깊이 카메라에서 발사한 광선이 통과한 셀은 free, 광선의 끝점은 occupied로 확률 갱신하며, 센서가 관측하지 못한 영역은 unknown 상태로 유지합니다.

Gazebo에서 구성한 UR5e 실험 장면입니다. 로봇의 목표 위치와 정적 장애물, 이동 중 진입하는 동적 장애물을 배치해 경로 재계획 상황을 재현했습니다.

지도 데이터량 변화가 임계값에 도달한 뒤 장애물 감지, 정지, 재계획 요청, 새 경로 실행이 이어진 로그입니다.

ROS 2 노드와 토픽의 연결 관계입니다. Gazebo, MoveIt2, OctoMap, trajectory controller와 재계획 노드 사이의 데이터 흐름을 확인할 수 있습니다.

04 · Design Decisions & Trade-offs

객체 인식보다 점유 지도 기반 장애물 표현

이 프로젝트에서 필요한 정보는 장애물의 의미 클래스보다 로봇의 계획 궤적과 점유 공간이 겹치는지 여부였습니다. 이에 객체 종류를 분류하는 YOLO나 ICP 기반 인식 대신 OctoMap을 선택했습니다. 깊이 카메라 점군을 free·occupied·unknown 공간으로 표현하면 별도의 학습 데이터 없이 Planning Scene을 갱신할 수 있습니다. 반면 장애물 종류나 이동 주체의 의도는 구분하지 못합니다.

MoveIt2·OMPL과 연속 충돌 검사

UR5e는 6-DOF 관절 공간에서 목표 자세까지 이동해야 하므로 MoveIt2와 OMPL의 RRT-Connect를 사용했습니다. RRT-Connect는 시작점과 목표점 양쪽에서 탐색 트리를 확장해 경로를 찾는 샘플링 기반 계획기입니다. 경로의 waypoint만 검사하면 waypoint 사이의 충돌을 놓칠 수 있어 Continuous Collision Check를 함께 적용했습니다.

지도 변화량은 장애물의 의미가 아닌 이벤트 대리 지표

실시간 감시에는 OctoMap/Planning Scene 데이터량의 bytes-diff를 사용했습니다. 약 160 bytes 임계값은 장애물의 위치·크기·위험도를 직접 판별하지 않고 지도 데이터의 변화만 감지하는 실험적 휴리스틱입니다. 별도 객체 추적이나 공간 위치 기반 비교를 구현하지 않은 개발 범위에서 재계획 이벤트를 단순하게 연결하기 위한 선택이었습니다. 복셀 갱신량이 실제 충돌 위험과 일치하지 않을 수 있어 장면 노이즈에 따른 오탐·미탐이 남습니다.

05 · Experiments & Results

Gazebo의 UR5e 시뮬레이션에서 Perception–Planning–Control–Recovery FSM이 연결된 반응형 재계획을 end-to-end로 동작시켰습니다. 지도 데이터량 변화(bytes-diff, τ ≈ 160)를 기준으로 동적 장애물 진입을 감지하고, 별도 인식기 없이 정지 → 후퇴 → 재계획 → 재개가 이어지는 것을 로그와 RViz에서 확인했습니다 (예: 14615 → 14455 (Δ160) 감지 → replan SUCCESS).

5회 반복 실험에서는 3회 성공(3/5, 60%)으로 기록되었으며, 팀 자체 평가 자율 동작 완성도는 약 86%였습니다. 이 수치는 Gazebo 시뮬레이션의 제한된 반복 결과이며 실제 UR5e 하드웨어의 성공률을 의미하지 않습니다. 남은 2회 실패의 원인을 동일한 기준으로 분류한 기록은 확보되지 않아 특정 원인으로 단정하지 않습니다.

RViz에서 Planning Scene에 반영된 OctoMap 복셀을 확인한 화면입니다. 깊이 센서가 관측한 공간 정보가 충돌 검사와 경로 계획에 사용됩니다.

동적 장애물이 경로에 진입한 뒤 로봇이 정지하고 후퇴한 다음, 새 경로를 계산해 이동을 재개하는 전체 시연입니다.

  • 실행 환경 — Ubuntu 22.04 · ROS 2 Humble · Gazebo Classic 11 · RViz 2 · Python 3.10 (rclpy)
  • Motion Planning — MoveIt 2 + OMPL (RRT-Connect), Continuous Collision Check
  • Perception — OctoMap (MoveIt OccupancyMapUpdater), Planning Scene 실시간 반영
  • Robot — UR5e (6-DOF, Gazebo Sim), JointTrajectory Controller
  • Team — 양태훈 (데이터사이언스) · 오상민 (AI) · 조윤재 (AI) — 인공지능종합설계 팀프로젝트

06 · Limitations & Reflection

현재 구현은 깊이 영상에서 점유 지도를 만들고, 지도 변화 이벤트를 기준으로 정지·후퇴·재계획·재개를 연결한 Gazebo 시뮬레이션 시스템입니다. 학습된 World Model이나 동적 객체 추적 모델을 구현한 프로젝트는 아닙니다. 또한 bytes-diff는 지도 변경량을 이용한 간접 지표이므로, 복셀 갱신량과 실제 충돌 위험이 항상 일치하지 않습니다.

후속 개선에서는 지도 변화량만 감시하는 방식에서 벗어나 변경된 복셀의 공간 위치와 계획 궤적의 충돌 구간을 함께 확인하고, 임계값 민감도 및 오탐·미탐을 별도 평가할 필요가 있습니다. 실제 UR5e와 깊이 센서에서의 지연·정지 거리·재계획 성공률도 시뮬레이션 결과와 분리해 검증해야 합니다.
