PROJECT 06

Dynamic Obstacle-Aware Path Replanning for a 6-DOF Robot Arm

인공지능종합설계 팀프로젝트 · UR5e (Gazebo Sim) · Reactive Recovery FSM
UR5e (Gazebo) Depth Camera (Sim) OctoMap MoveIt 2 RRT-Connect (OMPL) Continuous Collision Check Recovery FSM ROS 2 Humble · rclpy
Role Team Member (3인 · AI 트랙)
Period Aug. 2025 – Dec. 2025
Domain Robotics · Motion Planning (Sim)

S · Situation

정적 플래너만으로는 실행 중인 궤적에 갑자기 들어오는 동적 장애물을 회피할 수 없다. 실제 UR5e 하드웨어를 다루기 전, Gazebo 시뮬레이션 위에서 반응형 재계획 파이프라인의 동작을 먼저 검증할 필요가 있었다.

특히 팀프로젝트 특성상 장애물 감지 → 정지 → 후퇴 → 재계획 → 재개가 별도 인식기 학습 없이도 안정적으로 트리거되도록 설계 자체를 단순화해야 했다.

T · Task

  • Gazebo 상의 depth camera 스트림을 확률적 3D 격자(OctoMap)로 통합해 MoveIt2 planning scene에 반영한다.
  • MoveIt2 + OMPL(RRT-Connect) 위에 continuous collision checking을 얹어 궤적 수준의 미래 충돌을 예측한다.
  • 지도 데이터량 변화(bytes-diff)로 동적 장애물 진입을 감지하고, stop → back-off → replan → resume을 자동 트리거하는 recovery FSM을 붙인다.

A · Action

  • Perception 파이프라인 (Gazebo Sim) — Gazebo depth camera → PointCloud → OctoMap (OccupancyMapUpdater) → Planning Scene 반영. 별도 인식기(YOLO/ICP)를 학습·연결하지 않고, OctoMap이 유지하는 확률적 3D 점유 격자 자체를 장애물 표현으로 사용.
  • Motion Planning — MoveIt 2 + OMPL RRT-Connect로 시작–목표 관절공간 경로를 생성하고, Continuous Collision Check로 궤적 상태 사이 구간의 미래 충돌까지 예측.
  • Reactive Recovery FSM (bytes-diff 트리거) — Planning Scene의 지도 데이터량 변화(voxel bytes)가 임계값(τ ≈ 160 bytes)을 넘으면 동적 장애물 진입으로 판단, Monitor → Detect → Stop → Back-off → Replan → Resume을 순서대로 실행. UR5e는 JointTrajectory Controller로 실행/정지/재개.

* OctoMap 업데이트 원리 — depth ray를 따라 통과한 셀은 free, 끝점 셀은 occupied로 확률 갱신. 미관측 영역은 unknown 상태로 유지.

R · Result

Gazebo 상 UR5e에서 Perception–Planning–Control–Recovery FSM 4단이 결합된 반응형 리플래닝을 end-to-end로 동작시켰다. 지도 데이터량 변화(bytes-diff, τ ≈ 160)만으로도 동적 장애물 진입 → 즉시 정지 → 후퇴 → 재계획 → 재개가 별도 인식기 없이 트리거되는 것을 로그·RViz로 확인하였다 (예: 14615 → 14455 (Δ160) 감지 → replan SUCCESS).

5회 반복 라운드 기준 3/5 성공(약 70%), 팀 자체 평가 자율 동작 완성도 약 86% 수준으로 기록되었다. 한계로는 (1) bytes-diff 임계값이 장면 구성에 민감해 튜닝이 필요하고, (2) 실기 UR5e·실기 depth sensor 이식은 다음 단계 과제로 남았다.

  • 실행 환경 — Ubuntu 22.04 · ROS 2 Humble · Gazebo Classic 11 · RViz 2 · Python 3.10 (rclpy)
  • Motion Planning — MoveIt 2 + OMPL (RRT-Connect), Continuous Collision Check
  • Perception — OctoMap (MoveIt OccupancyMapUpdater), Planning Scene 실시간 반영
  • Robot — UR5e (6-DOF, Gazebo Sim), JointTrajectory Controller
  • Team — 양태훈 (데이터사이언스) · 오상민 (AI) · 조윤재 (AI) — 인공지능종합설계 팀프로젝트
