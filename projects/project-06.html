PROJECT 06

Dynamic Obstacle-Aware Path Replanning for a 6-DOF Robot Arm

인공지능종합설계 팀프로젝트 · UR5e (Gazebo Sim) · Reactive Recovery FSM
UR5e (Gazebo) Depth Camera (Sim) OctoMap MoveIt 2 RRT-Connect (OMPL) Continuous Collision Check Recovery FSM ROS 2 Humble · rclpy
Role Team Member (3인 · AI 트랙)
Period Aug. 2025 – Dec. 2025
Domain Robotics · Motion Planning (Sim)
이 페이지에서
Problem DefinitionSolution GoalsImplementationResults

전체 시스템 개요입니다. 깊이 카메라의 관측이 점군과 OctoMap으로 변환되고, MoveIt2/OMPL 경로 계획과 UR5e 제어로 이어집니다. 지도 변화가 감지되면 재계획 루프가 동작합니다.

01 · Problem Definition

정적 플래너만으로는 실행 중인 궤적에 갑자기 진입하는 동적 장애물에 대응하기 어렵습니다. 실제 UR5e 하드웨어에 적용하기 전에 Gazebo 시뮬레이션에서 장애물 감지부터 재계획까지 이어지는 반응형 파이프라인을 먼저 검증할 필요가 있었습니다.

팀 프로젝트의 개발 범위를 고려해 별도의 장애물 인식 모델을 학습하기보다, 지도 갱신 정보를 이용해 장애물 감지 → 정지 → 후퇴 → 재계획 → 재개가 연결되도록 시스템을 단순화했습니다.

02 · Solution Goals

깊이 카메라의 관측을 OctoMap으로 변환해 MoveIt2의 Planning Scene에 반영하고, OMPL 경로 계획과 연속 충돌 검사를 연결하는 것을 목표로 삼았습니다. 실행 중에는 지도 변화량을 감지해 동적 장애물이 진입했을 때 로봇을 정지시키고, 안전한 위치로 후퇴한 뒤 새 경로를 계획하도록 Recovery FSM을 구성했습니다.

03 · Implementation

깊이 영상에서 3차원 점유 지도 생성

Gazebo의 깊이 카메라에서 점군을 생성하고, MoveIt의 OccupancyMapUpdater를 통해 OctoMap으로 통합했습니다. 별도의 YOLO나 ICP 기반 장애물 인식기를 추가 학습하는 대신, 관측된 공간을 free·occupied·unknown 상태로 누적하는 확률적 3차원 점유 격자를 장애물 표현으로 사용했습니다. 이 선택으로 인식 모델 학습 없이도 계획 장면을 갱신할 수 있었습니다.

경로 생성과 연속 충돌 검사

MoveIt 2와 OMPL의 RRT-Connect를 사용해 시작 상태에서 목표 상태까지 관절 공간 경로를 생성했습니다. 경로의 이산 waypoint만 검사하면 waypoint 사이 구간에서 발생하는 충돌을 놓칠 수 있으므로, Continuous Collision Check를 적용해 궤적 구간의 충돌 가능성도 확인하도록 구성했습니다.

지도 변화량 기반 복구 상태 머신

동적 장애물이 들어올 때마다 별도의 객체 분류 모델을 실행하는 대신, Planning Scene의 지도 데이터량(voxel bytes) 변화를 감시했습니다. 변화량이 약 160 bytes 임계값을 넘으면 장애물 진입 이벤트로 판단하고, Monitor → Detect → Stop → Back-off → Replan → Resume 순서로 복구 절차를 실행하도록 구현했습니다. UR5e의 이동·정지·재개는 JointTrajectory Controller를 통해 제어했습니다.

Perception, Planning, Control과 Recovery FSM의 연결 구조입니다. 센서 정보가 Planning Scene에 반영되고, 지도 변화 이벤트가 로봇 정지와 재계획을 트리거합니다.

OctoMap의 점유 지도 갱신 원리입니다. 깊이 카메라에서 발사한 광선이 통과한 셀은 free, 광선의 끝점은 occupied로 확률 갱신하며, 센서가 관측하지 못한 영역은 unknown 상태로 유지합니다.

Gazebo에서 구성한 UR5e 실험 장면입니다. 로봇의 목표 위치와 정적 장애물, 이동 중 진입하는 동적 장애물을 배치해 경로 재계획 상황을 재현했습니다.

지도 데이터량 변화가 임계값에 도달한 뒤 장애물 감지, 정지, 재계획 요청, 새 경로 실행이 이어진 로그입니다.

ROS 2 노드와 토픽의 연결 관계입니다. Gazebo, MoveIt2, OctoMap, trajectory controller와 재계획 노드 사이의 데이터 흐름을 확인할 수 있습니다.

04 · Results

Gazebo의 UR5e 시뮬레이션에서 Perception–Planning–Control–Recovery FSM이 연결된 반응형 재계획을 end-to-end로 동작시켰습니다. 지도 데이터량 변화(bytes-diff, τ ≈ 160)를 기준으로 동적 장애물 진입을 감지하고, 별도 인식기 없이 정지 → 후퇴 → 재계획 → 재개가 이어지는 것을 로그와 RViz에서 확인했습니다 (예: 14615 → 14455 (Δ160) 감지 → replan SUCCESS).

5회 반복 실험에서는 3회 성공(약 60%)으로 기록되었으며, 팀 자체 평가 자율 동작 완성도는 약 86%였습니다. 다만 bytes-diff 임계값은 장면 구성에 따라 민감하게 달라질 수 있어 추가 튜닝이 필요하며, 실제 UR5e와 깊이 센서에 이식하는 작업은 후속 과제로 남았습니다.

RViz에서 Planning Scene에 반영된 OctoMap 복셀을 확인한 화면입니다. 깊이 센서가 관측한 공간 정보가 충돌 검사와 경로 계획에 사용됩니다.

동적 장애물이 경로에 진입한 뒤 로봇이 정지하고 후퇴한 다음, 새 경로를 계산해 이동을 재개하는 전체 시연입니다.

  • 실행 환경 — Ubuntu 22.04 · ROS 2 Humble · Gazebo Classic 11 · RViz 2 · Python 3.10 (rclpy)
  • Motion Planning — MoveIt 2 + OMPL (RRT-Connect), Continuous Collision Check
  • Perception — OctoMap (MoveIt OccupancyMapUpdater), Planning Scene 실시간 반영
  • Robot — UR5e (6-DOF, Gazebo Sim), JointTrajectory Controller
