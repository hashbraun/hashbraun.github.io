PROJECT 05

SMIM — On-Device Personal Memory Agent

Ambient Recall: 작성 중 맥락 감지 → 개인 문서에서 검증된 근거 카드 · 100% on-device · 2026 AI·SW중심대학 디지털 경진대회 SW부문
Electron Native AI Runtime granite-embedding-311m Qwen 3B / 4B / 7B LanceDB Hybrid Retrieval (BM25 + Vec + RRF) Cross-encoder Rerank Corrective / Reflection Loop Grounding Validator pytest (150 cases · model-free)
Role Team Member (Retrieval & Agent)
Team 이어인하다 · 5명 (AI · CS · EE · Design · Business)
Period Jul. 2026 – Aug. 2026
Domain On-device Agent · Hybrid RAG · sLLM

S · Problem Definition

지식 노동자는 스치듯 본 자료를 다시 찾기 위해 주 5.3시간을 검색·전환에 소비하고, 그 결과 재생산에 소요되는 시간의 50% 이상이 "이미 본 것을 다시 찾는" 과정에 낭비된다 (McKinsey · IDC).

기존 검색·챗 기반 도구는 능동적으로 다시 꺼내주지 못하고, 개인 문서를 클라우드로 올려야 해 프라이버시·규제 리스크가 크다. 필요한 것은 작성 중인 맥락을 감지해서 원문 근거가 붙은 카드를 온디바이스에서 스스로 꺼내주는 에이전트다.

T · Scope & Design Goals

  • 사용자의 작성 맥락 변화를 감지해 관련 개인 문서를 스스로 꺼내주는 Ambient Recall 파이프라인을 설계한다.
  • Sparse + Dense를 안정적으로 융합하고, 재랭킹·구조 신호까지 얹은 Hybrid Retrieval을 만든다.
  • 생성된 카드가 원문에 근거하는지 검증하고, 저품질일 때 스스로 교정/재생성하는 이중 루프를 만든다.
  • Ollama/LanceDB가 없는 환경에서도 안전하게 리팩터링할 수 있는 모델-프리 pytest 인프라를 갖춘다.

* 팀 내 본인 담당은 Retrieval 파이프라인 (Hybrid + Rerank + 구조신호)과 Agent 자기 교정 루프 (Corrective / Reflection / Grounding Validator)이다. Electron UI·디자인·비즈니스 파트는 별도 팀원이 담당했다.

A · System Design & Implementation

담당 영역과 설계 방향

팀 내에서 Retrieval과 Agent 동작을 맡아, 기능 범위와 품질 기준을 정의하고 검색 엔진·자기 교정 루프를 구현했습니다. 검색 결과를 더 잘 찾는 것뿐 아니라, 생성된 카드가 원문에 근거하는지 검증하고 실패 시 안전하게 보류·재시도하는 흐름에 집중했습니다.

  • Feature scope: Ambient Recall을 위한 맥락 감지 이후 검색·카드 제안의 경계 정의
  • Retrieval: BM25 + Vector + RRF + reranking 및 문서 구조 신호 통합
  • Agentic memory loop: Corrective query refinement, Reflection regeneration, Grounding validation
  • Quality: 모델 런타임 없이 검증 가능한 150개 pytest 케이스

전체 시스템은 Electron Application + Native AI Runtime 2-계층으로 나누어 UI 반응성과 AI 성능(CPU · GPU · Neural Engine)을 분리하고, 100% 온디바이스로 개인 문서가 기기 밖으로 나가지 않도록 설계했다. 본인은 이 중 파란색으로 강조된 Hybrid Retrieval과 Corrective / Reflection 루프 + Grounding Validator를 담당했다.

검색·에이전트 아키텍처와 구현 상세 보기
  • Hybrid Retrieval (담당) — BM25 (키워드 · 수치 · 전문 용어) + Vector search (granite-embedding-311m · 768d)를 RRF (Cormack et al., 2009)로 융합하고, Cross-encoder re-ranker로 Top-K를 최종 정렬. 여기에 tier · recency · view 등 구조 신호를 가중치로 얹어 관련도를 보정.
  • Corrective-RAG 외부 루프 (담당) — Query Planning 단계에서 의도를 분해하고, Grounding 근거가 부족하면 low_confidence로 판정해 쿼리 refinement를 자동으로 재실행.
  • Reflection 내부 루프 (담당) — sLLM이 카드마다 self-critique를 수행하고, 저점 카드는 critique-guided regeneration. 2회 재시도 후에는 keyword-based 카드로 폴백.
  • Grounding Validator (담당) — 생성된 카드의 각 주장을 원문 청크와 대조해 근거가 없는 문장을 걸러내고, 근거가 약하면 카드를 보류 상태로 유지. Structured output으로 카드 스키마를 강제해 파싱 실패를 원천 차단.
  • Ingest Pipeline — 개인 문서 → 파싱 → Semantic Chunking → granite-embedding-311m (768d) → LanceDB. 인덱싱은 사용자 노트 폴더 선택 → 권한 설정 → 로컬 sLLM 설치 순 온보딩으로 시작된다.
  • 모델-프리 pytest suite (150 케이스 · 5 modules) — RRF 공식, BM25 캐시, 쿼리 플래너, 재랭킹, 카드 검증을 Ollama · LanceDB 없이 검증해 리팩터링 안정성을 확보.

* SMIM 데모 영상 — 사용자가 노트를 작성하는 도중 SMIM이 스스로 관련 개인 문서를 꺼내 근거가 붙은 카드로 제안한다.

R · Evaluation & Outcome

검색 품질 평가: 19개 문서에서 구성한 40개 청크와 10개 질의를 사용한 자체 벤치에서, vector-only 기준 대비 Hybrid Retrieval(full_current)의 MRR@3는 0.70 → 0.95, Hit@1은 60% → 90%로 개선되었다. BM25와 Vector를 결합한 설정은 검색 후보의 상위권 적중을 높였고, reranking과 문서 구조 신호를 더한 최종 구성은 작은 자체 벤치에서 높은 검색 품질을 보였다.

생성 파이프라인 평가: 26개 카드 생성 E2E에서 21개(81%)는 sLLM 카드로 생성되었고, 5개(19%)는 keyword 기반 폴백으로 처리되었다. 평균 지연은 17.3초, p95 30.5초였다. 이는 생성 실패를 무조건 오류로 끝내지 않고 대체 경로로 처리하는 동작을 확인한 결과다.

회귀 테스트: RRF 계산, BM25 캐시, Query Planner, Re-ranker, 카드 검증의 5개 모듈에 대해 모델 런타임과 LanceDB 없이 실행되는 pytest 150개를 구성했다. 검색 벤치가 실제 검색 순위 품질을, E2E가 생성·폴백 흐름을 확인한다면, 이 테스트 묶음은 각 모듈의 결정적 로직을 빠르게 반복 검증하기 위한 것이다. 다만 현재 문서에는 pytest의 개별 fixture 데이터셋과 케이스별 통과 결과가 기록되어 있지 않으므로, 150이라는 개수 자체를 모델 품질의 증거로 해석하지 않는다.

해석: 이 결과는 Hybrid Retrieval이 해당 소규모 자체 벤치에서 검색 정확도를 높였고, Grounding·Reflection·폴백을 결합해 카드 생성 실패를 통제하는 구조를 확인했다는 근거다. 10개 질의의 결과이므로 일반적인 검색 성능으로 확대 해석하지 않고, 온디바이스 환경에서의 설계·검증 사례로 제시한다.
