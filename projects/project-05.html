PROJECT 05

SMIM — On-Device Personal Memory Agent

사용자가 문서를 작성하는 동안 입력 맥락을 감지하고, 로컬 문서 검색과 카드 생성을 거쳐 원문 근거가 확인된 추천을 제시하는 전체 사용자 흐름입니다.

SMIM (Smart Memory in Mind)는 작성 중인 맥락과 개인 문서 간의 연결을 찾아, 다시 검색하지 않아도 필요한 자료를 근거 카드 형태로 제안하는 온디바이스 개인 기억 보조 시스템입니다. 본인은 Hybrid Retrieval과 추천 Agent의 자기 교정·근거 검증 흐름을 담당했습니다.

01 · Problem Definition

개인 문서가 축적될수록 필요한 자료를 다시 찾는 과정은 문서의 위치와 표현을 기억하는 검색 문제로 바뀝니다. 그러나 작성 중인 사용자의 의도는 현재 문장만으로 완전히 드러나지 않으며, 단순 키워드 검색이나 문장 유사도만으로는 지금의 판단에 실제로 도움이 되는 자료를 구분하기 어렵습니다.

또한 개인 문서에는 업무·학습·개인 기록이 함께 포함될 수 있어 외부 서비스로 전송하지 않고 처리할 필요가 있습니다. 따라서 작성 맥락을 바탕으로 로컬 문서 후보를 찾고, 추천 내용이 원문에 근거하는지 확인하는 검색·생성 구조가 필요했습니다.

02 · Scope & Design Goals

  • 작성 맥락 변화 감지와 개인 문서 후보 검색을 연결하는 Ambient Recall 흐름 설계함.
  • BM25와 Dense Vector 검색을 결합하고 RRF·재랭킹·문서 구조 신호를 적용함.
  • 검색 후보를 바탕으로 추천 카드를 생성하고, 원문 근거 검증 및 재시도 경로를 구성함.
  • 모델과 벡터 DB 없이도 회귀 검증이 가능하도록 모델-프리 pytest 테스트 기반 마련함.

담당 범위: Hybrid Retrieval(BM25·Vector·RRF·Rerank·구조 신호), Corrective / Reflection Loop, Grounding Validator.

03 · System Design & Implementation

애플리케이션과 로컬 AI 실행 계층

시스템은 Electron Application과 Native AI Runtime으로 분리했습니다. UI 이벤트 처리와 모델 추론을 분리해 화면 반응성을 유지하고, 임베딩·검색·언어 모델 실행은 로컬 런타임에서 처리하도록 구성했습니다. 개인 문서와 임베딩, 생성 결과가 기기 밖으로 나가지 않는 대신 외부 검색·클라우드 모델·원격 도구를 사용할 수 없는 구조입니다.

Electron 기반 애플리케이션과 로컬 AI 실행 계층의 역할을 분리한 구조입니다. 본인은 로컬 문서 검색과 추천 Agent의 자기 교정·근거 검증 흐름을 담당했습니다.

문서 수집과 검색 인덱스 구성

개인 문서를 파싱한 뒤 Semantic Chunking으로 의미 단위 청크를 만들고, granite-embedding-311m(768차원) 임베딩을 생성해 LanceDB에 저장했습니다. 문서 전체를 매번 LLM 입력으로 전달하는 방식은 로컬 추론 비용과 문맥 길이를 빠르게 증가시키므로, 청크 단위 인덱스를 구성해 필요한 후보만 검색하도록 했습니다.

Hybrid Retrieval과 후보 순위화

BM25는 키워드·수치·고유명사처럼 표현이 정확히 일치해야 하는 단서에, Vector Search는 표현이 달라도 의미가 가까운 문장에 대응하도록 함께 사용했습니다. 두 검색 결과는 RRF(Cormack et al., 2009)로 결합하고, Cross-encoder 재랭커와 tier·recency·view 등 문서 구조 신호로 후보 순위를 보정했습니다. LLM이 모든 문서를 직접 읽는 대신 검색 단계에서 후보를 압축해 온디바이스 추론량을 제한하려는 설계입니다.

LLM 기반 맥락 추천 비교

검색 유사도와 현재 상황에서의 유용성이 다를 수 있어, 작성 맥락과 문서 내용을 LLM이 직접 읽고 추천하는 방식도 비교했습니다. 제한된 실제 문서·맥락 사례에서는 BM25·Vector 검색으로 찾은 후보가 LLM 단독 판단 결과보다 더 적합했던 사례가 관찰됐습니다. 표본이 적어 일반적인 우열로 해석하지 않았으며, 검색으로 후보를 찾고 LLM은 제한된 후보를 바탕으로 근거 카드를 생성하는 역할로 배치했습니다.

추천 카드 생성과 자기 교정

검색 후보를 바탕으로 sLLM이 추천 카드를 생성하도록 구성했습니다. 외부 Corrective Loop에서는 근거가 부족한 경우 low_confidence를 반환하고 검색 질의를 수정해 후보 검색을 다시 수행합니다. 내부 Reflection Loop에서는 카드별 self-critique 점수가 기준에 미치지 못하면 최대 두 차례 재생성하며, 이후에도 기준을 통과하지 못하면 keyword 기반 카드로 전환합니다.

검색 후보를 재정렬한 뒤 카드를 생성하고 원문 근거를 검증합니다. 근거 부족 시 검색 질의 수정 또는 카드 재생성을 수행하며, 검증을 통과하지 못한 카드는 확정 정보처럼 노출하지 않습니다.

Grounding Validator와 출력 제어

생성 카드의 각 주장을 원문 청크와 대조해 근거가 부족한 문장을 걸러내고, 검증 기준을 충족하지 못한 카드는 보류 상태로 유지했습니다. Structured Output으로 카드 스키마를 제한해 출력 형식의 일관성을 확보하고 파싱 오류를 줄이도록 했습니다.

실행 데모

작성 중인 문맥을 바탕으로 개인 문서를 검색하고, 원문 근거를 검증한 추천 카드를 제시하는 데모입니다.

04 · Design Decisions & Agent State Transitions

검색 단계와 생성 단계의 역할 분리

검색은 개인 문서 전체에서 관련 후보를 빠르게 좁히는 역할을, 생성 모델은 제한된 후보를 읽고 현재 맥락에 맞는 근거 카드를 구성하는 역할을 맡도록 분리했습니다. 이는 소형 로컬 모델에 전체 문서 집합을 매번 입력하는 비용을 피하면서도, 단순 유사도 순위만으로 추천 내용을 확정하지 않기 위한 선택입니다.

검색 결과의 보정 신호

BM25와 Vector 결과를 RRF로 먼저 결합한 이유는 두 검색 방식의 점수 척도가 달라 원점수를 직접 합산하기 어렵기 때문입니다. 이후 재랭커와 문서 구조 신호를 추가했지만, 자체 벤치에서는 RRF 단계보다 최종 구성의 MRR@3가 낮았습니다. 후보 순위를 추가 조정하는 과정에서 일부 질의의 관련 문서 순위가 밀렸을 가능성이 있으나, 현재 집계 결과만으로 재랭커와 구조 신호 중 어느 요소가 영향을 주었는지 분리할 수는 없습니다.

온디바이스 실행의 trade-off

외부 네트워크와 API를 사용하지 않는 조건은 개인 문서의 로컬 처리를 보장하지만, 모델 크기와 호출 횟수, 입력 문맥 길이가 응답 지연에 직접 반영됩니다. 검색으로 후보를 먼저 압축하고 제한된 후보에만 sLLM을 적용한 것은 프라이버시와 응답 비용 사이의 균형을 맞추기 위한 설계입니다. 반면 외부 검색·클라우드 모델·원격 도구를 활용할 수 없고, 기기 성능에 따라 응답 시간이 달라지는 제약이 남습니다.

Agent 상태 전이

  1. Trigger → Query Planning: 작성 중인 입력에서 검색 의도와 핵심 단서를 정리함.
  2. Hybrid Retrieval → Reranking: BM25·Vector 후보를 RRF로 결합하고 재랭킹·구조 신호로 정렬함.
  3. Card Generation → Grounding Validation: sLLM이 카드를 생성하고 각 주장을 원문 청크와 대조함.
  4. Corrective: 근거 부족 시 검색 질의를 수정하고 후보 검색을 다시 수행함.
  5. Reflection: 카드별 critique 결과가 기준에 미달하면 최대 두 차례 재생성하고, 이후 keyword 기반 카드로 전환함.

05 · Experiments & Results

검색 후보 순위 평가: 19개 문서에서 구성한 40개 청크와 10개 질의를 사용한 자체 벤치에서 Vector-only는 MRR@3 0.70, BM25+Vector를 RRF로 결합한 구성은 1.00, 재랭킹과 구조 신호까지 추가한 전체 구성은 0.95를 기록했습니다. BM25를 결합한 단계에서 순위 지표가 가장 높았고, 재랭킹을 추가한 최종 구성에서는 1.00을 넘지 못했습니다.

생성 파이프라인 평가: 26개 카드 생성 E2E에서 21개(81%)는 sLLM 카드로 생성되었고, 5개(19%)는 keyword 기반 폴백으로 처리했습니다. 평균 지연은 17.3초, p95 30.5초였다. 이는 생성 실패를 무조건 오류로 끝내지 않고 대체 경로로 처리하는 동작을 확인한 결과다.

10개 질의로 수행한 자체 검색 실험 결과입니다. 벡터 검색 단독, BM25와 벡터 검색의 결합, 재랭킹과 구조 신호를 추가한 전체 구성을 비교했습니다. 이 결과에서는 BM25를 추가한 구성이 가장 높은 MRR@3를 기록했으며, 재랭킹을 포함한 최종 구성은 별도의 trade-off가 있음을 보여줍니다.

06 · Limitations & Reflection

검색 벤치는 19개 문서에서 구성한 40개 청크와 10개 질의로 제한되어 실제 장기 사용자의 다양한 작성 맥락을 대표하기 어렵습니다. LLM 단독 추천과의 비교 역시 소수 사례에서 관찰한 결과이므로, 문서 유형과 작성 상황을 넓힌 평가가 필요합니다.

E2E 26회 중 21회는 sLLM 카드, 5회는 keyword fallback으로 완료되었으며 평균 17.3초, p95 30.5초가 소요되었습니다. 따라서 현재 구조는 근거가 부족한 생성을 폴백으로 처리하는 경로까지 확인했지만, 즉각적인 글쓰기 보조 경험을 제공하기에는 지연과 폴백 비율을 더 낮출 필요가 있습니다. 다음 평가에서는 문서 유형과 작성 상황을 확장하고, 추천 카드의 실제 활용 여부를 사람 평가로 확인하는 한편 지연과 폴백률을 함께 추적할 필요가 있습니다.
